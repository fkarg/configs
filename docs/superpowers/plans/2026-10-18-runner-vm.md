# Rebuildable GitHub runner VMs

Goal: run up to three independent Ubuntu/Docker runners for Epistree/backend-core
on Jolly without switching the host NixOS configuration.

Approved design: plain QEMU/KVM, pinned Nix shell, Ubuntu 24.04 cloud image,
cloud-init provisioning, persistent disposable qcow2 overlays. No host directory
or Docker socket mounts. Outbound networking can reach the host/LAN; this is not
a network sandbox. Registration tokens are streamed over SSH after provisioning,
never written into source or cloud-init. No GPU passthrough.

Implementation in `tools/github-runner-vm/`:

- [x] Pin host tools in shell.nix; pin Ubuntu image URL and checksum.
- [x] Add cloud-init template installing Docker and a checksum-verified runner.
- [x] Add numbered VM lifecycle commands: start, SSH, wait, register, stop,
  unregister, and explicit reset. Each instance has a separate overlay, SSH key,
  localhost SSH port, and GitHub runner name. Serialize instance operations.
- [x] Add a repeatable guest smoke test for Docker bind mounts, networks,
  service DNS, and runner readiness; run it against actual guests.
- [x] Verify first boot and provisioning, then start/register three instances.
- [x] Read-only review, fix findings, rerun affected checks, document operations,
  commit only this work. Report GitHub online status and observed jobs/checks.

Verification: shellcheck, shell.nix evaluation, real QEMU boot, cloud-init result,
Docker workflow smoke test, safe stop/start, GitHub runner API status. CI workflow
files are not changed. Reset remains an explicit destructive command and is never
used against a registered VM until it has been unregistered.

## Observed verification

All three cloud-init runs completed and Docker build/Compose service DNS/bind
mount integration tests passed. VM2 shutdown/start/reconnect passed. Duplicate
start and reset of a running registered VM refused. All three GitHub runner API
records report online with only Linux, X64, ubuntu-vm. A temporary HTTP probe
confirmed the documented host-loopback reachability through 10.0.2.2.

ShellCheck and shell.nix resolution passed. Fresh-context source review found
retry/recovery gaps and a missing build smoke test; fixed and re-reviewed with
no material findings. The independent Claude Opus 5.5 design review added the
network verification. Its passt suggestion was rejected after official source
research showed the proposed loopback-forward combination would break SSH;
plain QEMU user networking with its explicit limitation was retained.

Backend CI routing is a separate PR, Epistree/backend-core#1204, preserving native
ARM64 image builds while admitting Linux-only ordinary checks. Its first actual
run passed planning/lint/typechecks on VM1, then failed pulling the external
quay.io/minio/minio:latest image (401) before tests. Dependency investigation is
in progress separately; no merge is authorized.
